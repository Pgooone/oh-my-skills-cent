# 验收判据纪律（增量补充）

> 只记录 cc-multi-agent-dev-flow 引入的**新增量**；双层验收、承重 spike、
> 每卡 commit、lead 复核等既有实践不在此重复立规。2026-07-29 引入。

verifier 与 lead 终验时遵守：

1. **确定性区分判据**：同一观测在「真通过」和「真失败」下取值必须不同。
   禁用「数量=N」「页面能打开」这类两种结果下都成立的弱判据；禁靠肉眼。
2. **造数据复刻真实流程**：测试数据必须经真实链路产生，禁止预置「期望终态」
   再断言（例：验收「使用工作流」必须从注册表下载 → 预览 → 执行走来，
   不许预先把 skill 摆进目标目录）。
3. **验「已删/已变化」**：用「DOM 中不再出现」或「后端列表重取」；
   禁用页面内 fetch 探针（探针 4xx 会自造失败）。
4. **承重墙的端到端 verify 排在依赖卡接线完成之后**（接线前打 PASS = 假阳性）。
5. **杀进程按端口/PID**，严禁 `pkill -f` 宽匹配（WSL 实测自杀过包装 shell）。
6. **推送后独立核实**：`git ls-remote origin` 与本地 `git rev-parse` 完整
   hash 全等才算同步成功，不信 push 回显。
