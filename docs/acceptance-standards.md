# 验收标准（acceptance-standards）

> 来源：cc-multi-agent-dev-flow skill 的双层验收方法论，经项目化裁剪。
> 跨轮有效；每轮的收口卡与 verifier 指令必须遵守本文件。2026-07-29 引入。

## 1. 双层验收（缺一不可）

- **逻辑层**：独立 verifier 干净态复跑门禁 + **自写 fixture/驱动**断言 AC + 红线审计。
  逻辑层 PASS 仅是必要条件，可被端到端层推翻。
- **端到端层**：UI 改动 = 真浏览器（chrome-devtools MCP，留截图证据，`pageErrors=0`）；
  服务/库 = 真实环境实跑（真实输入 → 真实输出/副作用，非 mock）。lead 亲跑亲看。

## 2. 判据纪律（三条最易漏，每卡自查）

1. **确定性区分判据**：同一观测在「真通过」与「真失败」下取值必须不同。
   禁用「数量=N」「页面能打开」这类两种情况下都成立的弱判据；禁靠肉眼看低分截图。
2. **造数据复刻真实流程**：测试数据必须经真实链路产生，禁止预置「期望终态」的
   反向 fixture（例：验收「使用工作流」必须从注册表下载→预览→执行走来，
   不许预先把 skill 摆进目标目录再断言）。
3. **bugfix commit 必含根因**（先 why 后 what，按规模分层）。

## 3. 端到端判据细则

- **验「已删除/已变化」**：用「DOM 中不再出现」或「后端列表重新拉取」，
  **禁用页面内 fetch 探针**（探针 4xx 会污染错误日志、自造失败）。
- **断言写操作后果**：用轮询期望态/等响应，不用定长 sleep；先看服务端日志/状态码
  （防冷编译/未预热误判实现 bug）。
- UI 卡：`pageErrors=0` + 全 AC 确定性 PASS + 零回归。
- 端到端因环境受限跑不通时：替代证据（逻辑层多重真生产路径 + 同构已验闭环）
  + 显式决策 + **登记残留 gap**，不得静默放过。

## 4. 承重墙纪律

- 每个新「能力组合」都要专门 spike（不假设旧 spike 覆盖新组合）；
  spike GO 需多重确认（队员自跑 + 对抗复核含负对照 + lead 亲跑）。
- **承重墙的端到端 verify 必须排在其依赖卡接线完成之后**——接线前承重墙零生效，
  提前 PASS = 假阳性。

## 5. 进程与数据卫生

- 杀进程**按端口或 PID**（`netstat -ano | findstr :8477` → taskkill /PID），
  **严禁 `pkill -f` 宽匹配**（会误杀包装 shell 自身——本项目 WSL 实测踩坑）。
- 冒烟后清理全部 fixture（临时数据目录、假 CLI、假 skill），恢复真实状态。

## 6. 推送独立核实

- 推送后唯一判据 = **独立命令直查远端**：`git ls-remote origin` 与本地
  `git rev-parse` 完整 hash 全等。**不信 push 回显**。

## 7. 每轮收口卡（末位固定）

每轮最后一张卡固定为「端到端验收」：真浏览器/真实环境跑 proposal 全部 AC，
按本文件 §2-§5 执行判据纪律，留证据，回写 progress.md 验收结论
（逐条 AC + 踩坑「写给后人」）。
